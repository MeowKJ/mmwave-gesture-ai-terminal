# FLS2 屏幕诊断报告（2026-11-07）

## 结论

**纯色与硬件彩条均由用户确认全黑：显示输出验收失败。尚不能判定屏幕本体损坏，也不能证明屏幕完好。**

此前用户确认原屏、同型号替换屏均全黑，替换屏硬件彩条也全黑。本轮白/红/绿/蓝及彩条已实际执行；用户分别确认两项均“仍然全黑、没有亮光”。这是本轮直接目视反馈，不是沿用此前结果。
替换屏未在其他板上验证；用户没有万用表，也没有已知正常驱动板。因此缺少屏端电压/信号与良品对照证据，软件方法无法完成损坏鉴定。
优先检查两块屏共用的自制板供电、连接器、复位、MIPI 通路及配置，是排查顺序，不是已证实故障归因。

### 寄存器快照与测试副作用

- 正式 probe 前，两个 DSI 错误快照 int0=0、int1=0，FIFO=0x000A0010。
- probe 后 int0=0、int1=0x80，FIFO=0x000A0050；读引擎 busy 位仍置位。
- 本机 SDK 头文件将 int1 bit7 定义为 `dpi_pld_wr_err`。初次 USB 恢复日志中也曾出现 0x80，不能只归因本次 probe，更不能归因屏本体损坏。
- probe 恢复了主控模式、BTA、VCID 与 bridge 配置，但**没有确认读引擎恢复空闲**；后续对照显示基线前需重启/重新上电，不重复该 probe。
- `data=00,00,00` 是预先清零的缓冲，不是屏幕返回的 ID；不能写成“读到了全零 ID”。
- 这是额外的实验性 LL 有界读，不是完全原始官方启动行为；可能受供电、连线、BTA 设置、运行时切模式或诊断方法影响。

### USB 日志局限

`REPORT QUIET` 后 PONG 曾滞留，恢复 NORMAL 才出现旧回复。首次短等待无回复不能当作死机证据。
本轮保留周期报告并定期发 PING；仍有截断/延迟，采信完整字段，不能仅靠分段接收窗口认定每条回复严格属于紧前命令。

## 损坏结论边界与后续

1. 用户已确认本轮两项均全黑，可确认普通渲染和绕过 LVGL 的主控彩条均未出图；仍无法区分主板供电/布线/接触、屏组件故障及初始化/信号问题。
2. 没有仪器和良品对照板时，当前合理结论是“显示通路未工作，屏本体损坏未证实”，而不是“屏幕已坏”或“屏幕一定没坏”。
3. 最直接的后续是用同型号兼容的已知正常驱动板，先验证良品正常，再换待测屏，最后良品复测；控制配置、电源与连接方式一致。接触/排线仍需排除。
4. 若待测屏能在正常板显示，应转查自制板链路；若待测屏不能而良品前后均正常，才可将问题收敛到待测屏组件。
5. 换屏先断电；未核对网名与引脚方向前，不飞线加压或给细间距连接器带电探测。
