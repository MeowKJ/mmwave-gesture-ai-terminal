# C5 独立 SDIO 诊断

这是 `c5_hosted` 内的独立诊断子工程，不是 Hosted 的新默认固件。
基于本机 ESP-IDF 6.1 `examples/peripherals/sdio/slave` 的缓冲所有权与公开驱动接口，
不启动 Wi-Fi、BT、NVS、UART，不输出 C5 GPIO2（P4 GPIO6 音频共享线）。

应用发布 `M5D1` 签名、协议版本、阶段、复位原因、实际 ELF SHA 和 100 ms 心跳。
心跳读取用单字节 seqlock 防止多次 CMD52 撕裂。仅处理 64 字节包，原样回显，
发送完成前不把接收缓存交还 RX 驱动。错误保留状态，不主动软件重启。
早于 SDIO 初始化的故障仍不可见，不把缺签名直接判为芯片损坏。

P4 使用同一 SDMMC owner：先释放下载器，再显式单次复位 C5、1-bit/400 kHz 卡初始化一次；
要求 20 份有效签名/身份/心跳采样，心跳确实推进，再做 16 轮随机 CMD53 回显。
不重发数据写入、不自动重置失败设备，不与 Hosted 共用这些诊断寄存器。

此阶段直接测试 Flash 应用，**跳过自定义 RAM 程序**：当前 esp-serial-flasher 的
`protocol_sdio.c:sdio_mem_begin_cmd` 在 stub 运行时需重新进入 bootloader，
而项目回调默认不复位，且官方源码明确说明 RAM 程序可能与 stub 地址重叠。
未实现/验证安全 RAM 加载和重新枚举前，不调用该路径，不宣称 RAM 诊断已通过。

## 写入与恢复边界

工具先验完整备份 SHA、原分区/otadata，再生成诊断和恢复两套 app-only 清单。
仅支持已观察到的 `ota_0=0x20000/0x1e0000`、双 otadata 擦除后回退 ota_0 的布局。
只写诊断应用实际长度；恢复时写备份中 ota_0 的完整内容（包括尾部），逐区 MD5 校验。
不改 bootloader、分区表、otadata、NVS、校准和工厂区，不做整片擦除。

恢复镜像已生成不等于恢复实测完成。解除三根下载接地前，必须先确认诊断写入校验通过；
后续恢复仍可能需要用户重新拉低三脚，再由 P4 显式复位，不能保证故障应用免引脚自救。

入口和操作顺序见项目 `tools/README.md`。所有备份和恢复数据仅本地忽略目录保存。
