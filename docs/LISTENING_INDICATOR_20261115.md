# 首页「猫猫在听」提示

## 目标与实现

- 纯黑与黑白表情不变，仅在右下角 `(400,396)` 放一个原生 Lucide 32px 麦克风；无圆环、波形、文字或额外点击区。
- 胶囊内部 0..10px 的颜色填充来自真实输入 RMS，而不是自身播放音量、随机动画或句子长度。10Hz 输入采样，50Hz 平滑；仅重绘 32px 范围。
- 两个新鲜样本越过活动门限后显示，声学输入停止约 240ms 后隐藏；单次短脉冲不显示。任一有效麦克风通道可驱动，不要求双通道都有声音。
- 实际停止采集、页面切换、关机遮罩、输入过期 350ms、无效数值均隐藏并清理旧状态。唤醒事件只改变已显示填充的颜色，不能强制静音图标出现。
- 自身功放活动、待播放／正在播放的语音、音频自检及 300ms 尾窗全部抑制监听提示，设置页电平表和 ESP-SR 输入不因此修改。
- 这是本地音频活动门限，并非人声分类 VAD／ASR；较大外界声音仍可能触发。完整录音→ASR→AI 对话不在本轮新增范围。

## 验证边界

- 同套生产 LVGL 桌面预览：静音、轻声和较大输入三态；非设计稿或独立 mock。
- 真实 LVGL 回归覆盖静音、孤立短脉冲、单通道输入、容量变化、仅唤醒事件、自身播放抑制、旧数据过期、无效数值、页面进出、停止采集。固定表情时逐像素检查：徽标之外的像素完全不变。
- 生产 app adapter 回归验证功放／语音／自检和输出结束后 300ms 仍抑制提示。
- 声学工具已同步新语义：推理健康不要求图标常驻，真实声源播放期间要求显示填充，结束和静默控制要求隐藏；软件故障注入不能替代声学实测。
- 本轮构建、烧录、板上遥测和视觉验收结果分别记录，下方只追加已取得证据，不以代码返回代替实屏观察。

## 未决项与失败记录

- 实屏位置、大小和观感仍待用户目视确认；目前视觉证据是同套 LVGL 桌面渲染，硬件证据是实际输入／控件遥测，没有摄像头观察。
- `local-output.json` 首次脚本误把 `queued=1` 当作 `accepted=1`，已保留；重跑 `local-output-r2.json` 发现实际试听任务创建返回 `ESP_ERR_NO_MEM`（257）。本轮未改变音乐、音量或音频内存架构，不能宣称设备真实 PCM 播音测试已通过。该问题独立留待修复。
- `amplifier-gate.json` / `amplifier-gate-r2.json` 的循环电脑音源恢复断言未通过，且未记录该阶段 RMS，不能确定失败原因；报告保留。上述新测试改用每阶段独立播放并记录真实 RMS 后，抑制／新输入恢复通过，不据此宣称循环播放问题已定位。
- 当前未验收 Wi-Fi 联网、完整 ASR 对话或长期稳定性，未把这些项目纳入本轮通过结论。
