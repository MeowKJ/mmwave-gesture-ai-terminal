# Wi-Fi 全链路审查与修复（2026-11-13）

## 结论与验收边界

这不是仅仅改“扫描”按钮：项目存在产品构建配置、C/ABI、请求并发、扫描生命周期、凭据持久化和页面反馈的多层问题。**不能据此认为 C5 固件损坏，也不应反复重刷 C5。**

最严重的已取证问题是 Wi-Fi 数据结构 ABI 不一致。修复前产品 ELF 的真实 DWARF：

| 编译单元 | `sizeof(wifi_ap_record_t)` | `he_ap` 偏移 |
|---|---:|---:|
| `main/bsp_wifi_hosted.c` | 92 | 80 |
| Hosted `esp_wifi_weak.c` | 96 | 84 |
| Hosted `rpc_rsp.c` | 96 | 84 |
| Hosted `rpc_wrap.c` | 96 | 84 |

`main/CMakeLists.txt` 手工前置原生 `esp_wifi/include`，遮蔽了 IDF Remote 的 injected 头文件。Hosted 给应用的数组按 96 字节写入，应用却按 92 字节取下一项；单条读取同样可能写出栈对象边界。这直接解释了旧代码备注“第一条正常、后面乱码”，逐条读取并不是安全修复。

已移除该手工路径，通过真实 CMake 依赖传播 Remote 接口。正常 product/hosted 构建现在检查最终 ELF 中应用层、弱接口和 RPC 层的结构大小、成员偏移及位域布局；不一致或缺少证据直接失败，结果写入构建目录 `wifi_abi.json`。

当前测试报告保存在本地忽略目录 `firmware/p4_gesture/test-results/wifi-audit-20261113/`。**桌面/软件通过不等于 C5 射频扫描、屏幕触摸或互联网连接已经通过。** 最初 USB 未枚举，后经用户重新接线恢复 COM10；现已完成 P4 烧录、三轮真实扫描以及列表/滚动/密码页实屏验收。另只读观察到 ONLINE/DHCP；用户选择暂不追加连接测试，未测互联网访问，详见后文。

## 已修复的问题

| 问题 | 修复 |
|---|---|
| 原生/Remote 头文件导致 92/96 字节 ABI 分裂，可能越界 | 使用真实组件依赖；最终 ELF ABI 构建门禁 |
| 默认 product 编译关闭 Wi-Fi，网络页面仍提供扫描入口 | product 自动组合 Hosted 配置；迁移旧本地 sdkconfig，只修改 Wi-Fi 相关项；检查生成配置 |
| 默认值更新不覆盖旧 sdkconfig，容易误以为已启用 | 一次性显式迁移，保留显示/电源/音频配置与构建缓存 |
| 单槽请求无占用检查，可覆盖已接受的扫描/连接 | 状态检查、请求占位及复制在同一临界区；繁忙直接拒绝 |
| ERROR 下每次扫描新建 bringup 任务，失败还拉低共享 GPIO54 | 启动一次、单次有界 ATTACH，不复位 C5、不重建传输；扫描失败不触发硬件恢复 |
| 扫描到 SCAN_DONE 就提前 READY，结果尚未收集 | 结果提交后才结束 scanning；增加请求代次、完成代次、事件状态与错误 |
| 在线扫描被映射成“连接中”，一秒状态刷新又清掉扫描提示 | 连接状态和扫描状态分离，在线扫描保留 ONLINE |
| 忽略驱动/API 错误，用户只看到空列表 | 扫描失败保留上次成功列表，并给失败反馈；成功空扫描明确显示未找到 |
| 没有扫描超时、取消后迟到事件处理 | 20 秒截止、停止扫描和释放记录，短暂隔离取消事件 |
| ASCII-only 过滤丢掉全部中文网络；-100 dBm 以下被直接丢弃 | 保留 UTF-8/原始标识，缺字仅显示“网络 N”；保留合法弱信号，按 SSID 去重 |
| 逐条读取到六条就退出，不释放剩余扫描记录 | 使用 ABI 一致的批量快照和有界静态缓存，退出/失败均清理驱动列表 |
| 在 LVGL 回调中读写 NVS；请求拒绝前已永久覆盖旧凭据 | 回调只入队；缓存已保存凭据；获取真实 DHCP IP 后由工作任务保存 |
| SSID/password 两次独立写入可能留下新旧混合值 | 使用一个 NVS blob 保存整个配置，兼容读取旧格式 |
| 完整 32 字节 SSID、64 字节十六进制 PSK 被截断 | 按字节数组完整复制，不强行添加第 33/65 个 NUL；密码长度/PSK 格式校验 |
| 切换网络直接 set_config/connect，旧连接和主动断开被误判 | 有真实关联时等待主动断开事件；空闲时不等待不会到来的事件 |
| 加入失败进入 ERROR，旧重连服务只处理 READY，重试失效 | 三次、每次间隔 5 秒，失败不补预算；加入/DHCP 30 秒截止 |
| IP 事件任务调用同步 Hosted RPC，缺少 LOST_IP 处理 | 小栈事件只更新缓存，RPC/NVS 转至工作任务；IP 丢失撤销 ONLINE |
| Hosted 早于 UI 初始化 NVS，可能漏掉开机凭据 | Wi-Fi 工作任务显式初始化 NVS；失败仅反馈，不自动擦除 |
| 忙碌的保存网络连接被 UI 当成“没有密码” | 忙碌时不弹密码页；密码提交返回网络页不抢发自动扫描 |
| 扫描命令立即回复旧列表，无法证明新扫描完成 | SCAN 只确认接受；STATUS/APS 带代次；逐项 AP 查询携带完成代次 |
| 多个长 SSID 的 USB 回复可能超过实际 512 字节 TX 门限 | 摘要与逐项查询分开，每条回复独立入队；SSID 使用十六进制避免空格/逗号破坏帧 |
| 状态和 AP 列表分别加锁读取，可能把旧列表标成新完成代次 | UI 与 USB 使用一次临界区的完整快照；STATUS 中的 SSID 也改为十六进制，避免名称伪装协议字段 |

## 实机验收入口

```powershell
python tools/meoave.py build --profile product
# 主板原生 USB 可见后，仅烧 P4；不写 C5，不追加硬件复位。
python firmware/p4_gesture/flash_usb.py --build-dir build_meoave --report test-results/wifi-p4-flash-01.json
python tools/wifi_acceptance.py --cycles 3 --report firmware/p4_gesture/test-results/wifi-scan-01.json
```

扫描工具核对最终 P4 ELF、供电保持和故障记录，连续发出三次独立扫描，各次只发一次变更命令，然后只读轮询，要求同代次完成、真实驱动计数与有效 AP。全部为空只能说明扫描调用完成，不算射频接收验收通过。报告必须是新文件，不覆盖历史证据。

工具不发送密码、不 JOIN、不刷机、不复位 P4/C5、不控制下载三脚。实屏是否显示相同网络及点击/密码输入，需要单独目视与触摸确认。

## 本轮未宣称完成的内容

- 新 P4 已烧录，真实扫描与上述实屏入口通过；这不是整条联网链路或长期稳定性的通过声明。
- 当前固件已观察到关联/DHCP，但用户主动连接流程、DNS、HTTPS、重启持久化/自动重连与长期稳定性仍待另测。
- 不承诺启动 ATTACH 失联可自动修好 C5；当前优先保证共享 GPIO54 安全，无隐藏复位。
- UI 目前仍只保存一个网络，最多缓存六个不同 SSID；同名不同安全策略/企业认证/隐藏网络管理未在本轮扩展。
- Legacy USB `WIFI SET/JOIN` 是空格分词语法，含空格 SSID 应使用屏幕；AP 查询采用十六进制没有该限制。
- 凭据使用现有 NVS 分区；没有在本轮启用 NVS 加密、修改分区或擦除用户设置。
