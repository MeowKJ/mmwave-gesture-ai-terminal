## 用户操作约定

1. 所需软件和测试镜像准备、离线检查完毕后，才提示用户将三脚接地并保持。
2. 用户回复后，P4 在雷达未运行的条件下复位 C5 一次，使下载状态被重新采样。
   仅把三脚拉低、不复位，不能视为已进入下载模式。
3. 尽量在同一下载会话完成识别、备份和所需写入；不要每做一项就让用户拆接。
4. 需要从 Flash 启动时才提示全部解除接地；P4 再执行一次受控 C5 复位并观测。
   解除接地本身不被当作已经退出下载程序。
5. 普通诊断可控制在一次接地、一次解除；若需要替换测试镜像或恢复旧固件，可能需要
   下一轮同样操作。不能保证所有迭代只需一次，也不保证故障固件能自救进下载模式。

## 分层测试与分支

### A：下载环境下的只读取证

由 P4 安装独立 programmer profile，确保 Hosted 与 programmer 不同时拥有 SDIO。
先建立一轮有界连接：ROM 下载链路会上传并运行官方 RAM flasher stub；
因此“Flash 只读”不等于不改变 RAM 或不执行目标代码。

已实现并实测：芯片/Flash 身份、允许的只读启动相关寄存器、Flash 小块读取及校验。
先读取小区域测试读接口，再分块备份整个 4 MB Flash，通过 USB 回传并校验，
至少对启动所需区域重复读取核对；读失败立即停止，不自动转为重刷。

核查 bootloader、分区表、两份 otadata、实际选择的应用、应用头/芯片限制/校验和。
若保有历史成功烧录镜像则比较；不得拿后来重新构建的不同 payload 冒充历史镜像。
只读保存启动寄存器原值，不写 eFuse、安全配置或强制下载位，不以下载状态下的
strap 值反推之前正常启动时的状态。

本地 esp-serial-flasher 的实现包含 SDIO stub 接收/ACK 和 Flash 读取路径，虽头文件
部分说明仍写串行接口限定，本轮已先小块后整片实测完成备份，详见本轮执行进度。

判读：备份/校验失败先处理下载链路或镜像问题；稳定成功只证明该环境中的 CPU、
RAM stub 与 Flash 访问，不证明从 Flash 启动或 Hosted 正常。

### B：无 Flash 改写的最小 RAM 程序（优先评估可行性）

构建专门的 C5 RAM 诊断程序，不使用 Wi-Fi、蓝牙、NVS 或 GPIO2 输出，
只初始化 SDIO、发布签名/版本/心跳，并提供小数据包 nonce 回显。
由 P4 读取寄存器与实际 CMD53 数据验证，不把“有 SDIO 应答”作为程序执行证明。

注意当前库的 SDIO mem_begin 在 stub 运行时会调用 enter_bootloader 并重新初始化，
本项目现有回调是 no_reset，不能直接假定上传任意 RAM 程序即可工作。
实施前须解决 stub/RAM 地址重叠、复位回调、独占 owner 与跳转后重新枚举顺序；
不使用普通 Flash-mapped IDF 镜像冒充 RAM-only 程序。若该路径不可靠，跳过并明确
记录为未执行，不在此无限重试；转入已备份后的 C。

判读：RAM 诊断成功说明能执行自定义代码并走应用 SDIO 数据通路，
将问题重点收敛到 Flash 启动链或完整 Hosted 初始化，但仍不构成完整硬件验收。

### C：已备份后的最小 Flash 诊断程序

在明确保留/恢复方案后，按生成的真实布局写入最小诊断镜像及必要启动选择数据，
逐区校验，不整片擦除，不触碰未知校准/工厂区；bootloader/分区表仅在证据需要时修复。
用户解除三脚接地，P4 单次复位 C5。

最小程序只做 SDIO：签名、构建身份、启动计数/复位原因、持续心跳、nonce 回显。
先寄存器通信，再 CMD53 小包双向校验，再短时有界稳定性检查。

判读：RAM 能跑、Flash 版不能跑，优先检查 Flash 启动链/镜像配置；
Flash 版能跑，重点检查完整 Hosted 的初始化与通知逻辑。
两者都失败且下载仍稳定，仍不足以判定芯片损坏。

### D：完整 Hosted 的分阶段可观测版本

在最小诊断通过后才恢复 Hosted。保留专用诊断寄存器协议，先做最小 SDIO/心跳，
再记录 NVS、Hosted SDIO、RX 缓冲装载、OPEN_DATA_PATH 回调、INIT 发送及 RPC 阶段。
共享寄存器须审计 Hosted 使用范围，分配互不冲突的字段；切换初始化可能清空标记，
因此协议还需区分阶段有效性/构建身份，不能把被清零当作未执行。
对发生在 SDIO 初始化之前、无法发布标记的故障，承认观测盲区，必要时使用经验证的
保留内存记录及专用读取程序，不承诺仅靠同一条 SDIO 链路能输出所有早期日志。

逐项启用，避免同时改变总线速率、Flash 频率、NVS、蓝牙与 Wi-Fi；
先在已知可通信的低速配置验证 INIT/型号/固件版本，再扫描和联网。

### E：后续免引脚升级

仅在 Hosted 通信真实通过后验收双槽 OTA：写非活动槽、校验、切换、复位重连，
并验证升级后健康确认/回滚配置与失败恢复，不把双槽存在等同于自动回滚已经有效。
用户无硬件改动时，应用和启动链均失效仍可能需要再次三脚接地恢复，不能承诺永远免操作。

## 执行纪律

- 每阶段输出独立 JSON，区分操作是否完成、数据是否有效和功能是否通过。
- 受控复位要求 radar=0；保留 P4 GPIO29、电源保持、显示初始化、180° 方向与原生 USB。
- 变更命令使用 nonce 且只发一次，丢 ACK 只查状态；失败停止，不补刷、不无限重启。
- 除本轮执行进度明确列出的已验证能力外，RAM 自定义程序、心跳固件、OTA 仍是后续计划。
